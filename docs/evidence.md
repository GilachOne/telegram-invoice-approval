# Основания для описания кейса

Дата осмотра: 23 ноября 2026 года. Источник: авторизованный интерфейс редактора Leadteh. Проверка состояла в чтении конфигурации; рабочие настройки не менялись.

| Утверждение | Основание |
|---|---|
| Общая структура главного сценария | Обзорный снимок 00: все блоки и связи на масштабе 20%; область аккаунта исключена из кадра |
| Формат суммы проверяется регулярным выражением | Открытый блок «Сумма», скриншот 01 |
| Данные заявки записываются в 14 колонок | Открытый блок Google Sheets основного сценария, поля A–N; скриншот 02 показывает начало сопоставления |
| Есть инструкция по распределению расходов | Открытый блок «Комментарии к расходам», скриншот 03 |
| Акт связан с ID платежа | Поля `id_payment` и `payment_proof` блока Google Sheets, скриншот 04 |
| Подписанный акт запрашивается как файл | Текст «Прикрепите подписанный акт в PDF», валидация «Файл» |
| Подпись документа формируется JavaScript | Прочитан блок с `getContactVariable` и `setContactVariable` |
| Документ передаётся через HTTP | POST, multipart/form-data, поля документа и подписи |
| Направление выбирается опросом | Блоки `sendPoll Направление`, `stopPoll Направление` и пользовательская инструкция |

## Что не подтверждено этим осмотром

Доставка сообщений и файлов, успешная запись новой заявки, принятие решений согласующими, автоматическое обновление статусов и обработка реакций внешним сервером, объём использования, коммерческий эффект.

## Публичные материалы

В репозитории отсутствуют токены, адреса служебных обработчиков, ссылки на рабочие реестры, ID чатов, usernames сотрудников и финансовые документы. Скриншоты показывают выбранные участки настроек без этих сведений. JavaScript содержит демонстрационные имена вместо реальных получателей.
